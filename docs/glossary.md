# 术语表（Glossary）——Core 架构术语

> 定位：全仓库**架构术语**的唯一权威（文档侧）。语言关键字以 `src/compiler/lexer.cr` 为唯一真源（本表不重复）。实现与文档冲突时以源码为准（既有惯例）。
>
> 状态：2026-08-27 v3——全量扩充（v1 = 57 行主条目；v2 = 全量术语；v3 = 补执行/并发/内存实现/编译器管线/讨论判据）。术语演进记录见 §十三。

## 一、哲学与约束

| 术语 | 含义 | 出处 |
|---|---|---|
| 语义保鲜 | Core 存在的理由：IR 保留全部语义与执行硬件解耦——范式迁移时语义不动、只换后端映射 | `z-vision.md` |
| 范式普适 | 语言跨越所有计算范式（含未来未知范式）——不是堆叠，是统一空间让范式差异被映射进去 | 备忘 §2.1 |
| 零硬件惯例 | 核心语义纯数学/逻辑/结构；硬件惯例只允许以「后端实现选择」或「可忽略注解」存在 | 备忘 §2.1 |
| 用户面上手成本极低 | 任何要求用户学习的新概念都是成本（YAGNI 默认：不加） | 备忘 §2.1 |

## 二、三层映射

| 术语 | 含义 | 出处 |
|---|---|---|
| 图（HDFG） | 关系空间：发生什么——节点 = 操作、边 = 值流、region 嵌套 = 控制流、state edges = 顺序约束；超图灵性属于图 | `dataflow-design.md` |
| 格（层） | 状态/存储空间 = 中间存在空间：如何存在——条目、配方、驱逐、再生 | `memory-model.md`；备忘 §四 |
| 编码（层） | 物理编码空间：如何实现——把格编码到具体机器（2026-08-27 更名，原「二进制」） | 备忘 §四 |
| 格（Lattice） | 层内组织代数成分（偏序 + join/meet）——**映射参数，非层本体承诺**（无格承诺） | 备忘 §4.4/§4.6 |
| 范式映射表 | 映射正确性定理表——经典行/量子行 = 证明缓存语义 ⊇ 该实现；寄存器映射实例 = 一行 | `z-vision.md` |
| 关系空间 / 存在空间 / 物理编码空间 | 图/格/编码三层的数学定位（发生什么 / 如何存在 / 如何实现） | 备忘 §4.2 |

| 术语 | 含义 |
|---|---|
| `.cr` | 源码 |
| `.cir` | 图形态：HDFG + 规约约束（验证 IR） |
| `.ccr` | 格形态：**Core Region Representation**（v6 演进中；现 v5 = 格层线性投影） |
| `.corespec` / `.csr` | 规约层：规约源码 / 规约 IR |

| HDFG | 全息数据流图——Core 唯一执行语义 |
| region（SG 段） | 图锚定存在结构（kind/enter/exit/parent/nstart/ncount）；区域 = 子图节点的字节域 |
| 线性投影 | 格形态 v5 = 从图线性化的投影形态（后端消费）；v6 升级为存在结构本体 |

## 四、缓存语义（`memory-model.md` §一 七条 + 4b）

| 术语 | 含义 | 条款 |
|---|---|---|
| 条目（entry） | 存储的一项：语义 = (产生它的图节点, 输入边) | 1 |
| 配方（recipe） | 值的产生方式 = 配方节点 + 输入边 | 1 |
| 驱逐（eviction） | 丢弃存储物、保留配方 | 2 |
| 驱逐不变量 | ⟦G ∖ storage(e)⟧ = ⟦G⟧——驱逐任意条目不改变可观测语义（语义保持定理；分配正确性的依据；order-free） | 2 |
| 再生（regeneration） | 重跑配方节点产生可观测等价的值 | 3 |
| 再生等价 | 再生值与原条目可观测等价——rematerialization 的依据 | 3 |
| 边界（boundary） | 图边界无配方条目（MMIO/FFI/输入/测量）；语法层 = `unsafe` | 4 |
| 边界公理 | 边界条目 = 符号常量；边界之外才需要 state | 4 |
| 图内不可重算 | 图内无配方条目（神谕/BSS 实数/FIXPT 声明/模糊融合）——驱逐/再生对其不成立 | 4b |
| 无配方条目 | 边界 + 图内不可重算——必须有 home、驱逐必写回（一视同仁，不按范式枚举） | 4/4b |
| 版本化 | 赋值 = 版本化：x₁ 诞生、x₀ 作废、绑定移动（「可变」= 绑定可移动的许可） | 5 |
| 地址 = 映射 | `&x` = (条目标识, 偏移)；字节地址只是经典投影 | 6 |
| 映射实例 | 缓存语义在具体机器上的实现（区域/arena/字节权限/寄存器/格代数） | 7 |
| 映射实例正确性 | 映射实例保持条款 1–6 可观测语义 = 范式映射表的行定理 | 7 |
| 字节权限层 | Freeable > Writable > Readable > Nonempty > Empty——经典映射实例的权限面 | 7 |
| home | 条目的持久位置（经典映射 = 栈槽） | — |
| 存在区间 | 条目在图层上的存活区间 = 图活性（RegionCheck cur_seq/exit_seq 机制） | — |
| 图活性 | 条目的存活区间（生命周期 = 图活性，非 LIFO） | — |
| 共存 | 两个条目的存在区间相交——对称关系，无传递性 | — |
| 驱逐配对 | 驱逐时材料不丢：写回 home，或配方可再生（= remat）；无配方条目必写回 | — |

## 五、寄存器分配（缓存语义映射实例，`regalloc-cache-mapping.md`）

| 术语 | 含义 |
|---|---|
| 一致性判定 | 单层验证：共存互斥 / 读点无陈旧 / 驱逐配对 / 调用失效——可判定、局部、条目泛型 |
| 共存互斥 | 每时刻每寄存器至多一个条目的材料 |
| 读点无陈旧 | 读到的材料与条目的当前版本对齐 |
| 调用点失效契约 | 调用点 = 缓存失效边界：caller-saved 失效（材料归 home）、callee-saved 保留（ABI = 缓存保留契约） |
| rematerialization（remat） | 配方重算恢复材料（条款 3 再生等价） |
| 共存偏序 width | 最小寄存器数（Dilworth 定理）；区间序 First Fit 贪心 = 最优 |
| order-free 正确性 | 驱逐不变量对全部可能执行成立——强于 CFG 正确性（只对一个线性化成立） |
| spill（溢出） | 寄存器压力下条目的材料移 home（驱逐的分配侧形态）——装载/存储成对 |
| 栈槽（stack slot） | home 的经典实现（函数相对偏移，disp8 友好） |
| 装载 / 存储（load/store） | 材料在 home 与寄存器缓存之间的移动（fill / write-back） |
| 写回（write-back） | 驱逐时材料写回 home（无配方条目必写回） |
| 缓存失效 | 调用点失效契约的动作（caller-saved 材料归 home） |

## 六、能力（治理层，备忘 v4 §六）

| 术语 | 含义 |
|---|---|
| 能力 | 治理层概念（v4 定论：**不提升一等公民、可逆、暂不执行**）——语义内容已还原图上（身份 = 图节点、无配方 = 标注） |
| 授权集 | consult / assume / measure / pass——「可能关系」标注，非语义本体 |
| 域约束 | 语义边界（类型签名），非字节长度 |
| 派生源 | 逃生舱授权从哪个声明/能力派生——信任链可追踪 |
| 能力树 | 寻址/派生/撤销/隔离一体（seL4 CNode / KeyKOS-EROS 先例；编译期兑现，运行期零新增） |
| 逃生舱 | 不可验证/不可追踪入口（与 unsafe 同层；验证侧对应 = ω-规则） |
| 可能关系 | A ──可能执行──> B——授权标注的图形态（与模糊/非确定统一） |
| 能力流分析 | PointerAnalysis 推广——能力如何派生/传递（编译期消费） |
| PCM | 偏交换幺半群：`·` 分离组合、序从组合导出——区域分量代数（Iris ghost state 底座） |
| 幂集格（布尔格） | 授权分量代数：⊆ 收窄 = 细化，∩/∪ = meet/join |
| 保序积 | (r₁,a₁) ⊑ (r₂,a₂) ⟺ r₁ ⊑ r₂ ∧ a₁ ⊆ a₂——PCM × 布尔格的组合方式 |
| 分数权限 | Boyland π ∈ (0,1] 分级授权——模糊隶属度 [0,1] 同构，扩展点（当前 YAGNI） |
| 可复制性 | 只读/consult = 可复制（share），写/assume = 独占（Iris 1.0→1.1 RA duplicable core 教训） |
| 声明式进图 | alloc_at 先例：声明即注册、生命周期随子图（句柄不透明） |

## 七、律与原则（v4 定稿）

| 术语 | 含义 |
|---|---|
| 律封闭、物开放 | 层本体零签名（缓存七条永不新建 = 维护有界）；物（条目/配方/标注）无界（= 表达无界） |

## 八、执行标注空间（`dataflow-design.md` §8）

| 术语 | 含义 |
|---|---|
| ITER | 迭代语义（因果循环，现状） |
| FIXPT | 一致解语义（非因果环）——声明性、执行后置 |
| 一致解 | 环上算子的不动点——值使环自洽，不迭代执行 |
| Knaster-Tarski 不动点 | μ/ν 最小/最大不动点——FIXPT 语义的理论（验证内核既有理论） |
| FUZZY | 模糊软分支（格值隶属度 [0,1]，两路执行按隶属度加权融合） |
| t-范数 | 模糊逻辑合取算子——Lukasiewicz / Gödel / Product 三种基本选择 |
| 剩余格 | 模糊逻辑代数底座（t-范数 + 蕴涵，Hájek BL-代数系） |
| Oracle（神谕） | 超图灵·神谕：「此节点计算函数 F」，F 可不可计算；跳变层级 ∅ < ∅′ < ∅″（Turing 1939） |
| BSS | 超图灵·连续：无限精度实数 = 原子符号（Blum-Shub-Smale） |
| ITTM | 超图灵·超限：序数时间位置、limsup 极限阶段（Hamkins-Lewis） |
| CORE | 共归纳：流 = 终余代数（F X = D×X）——同步数字电路的语义；可验证，非逃生舱 |
| CoNode | 流节点 = (S→T×S)×S（I/O 转导器形态） |
| 保护递归 | ▷ 算子 + Löb 不动点——生产率保证 |
| 双相似 | 共归纳观察等价（流等价） |
| ω-规则 | 无穷长推导规则——超图灵结构验证的形式化对应（内核理论已预埋） |

## 九、验证体系（`spec-design.md`）

| 术语 | 含义 |
|---|---|
| 规约层 IR | 程序「应该做什么」——前置/后置条件、循环不变量、抽象规约 |
| requires / ensures | 函数规约的前置/后置条件子句（corespec.ebnf） |
| loop invariant / loop variant | 循环不变量 / 循环界（终止性） |
| `#check` / `#ensure` / `spec fn` | 用户面规约语法（不需要学数理逻辑） |
| 翻译桥 | 规约 → CIC 项的自动编译 |
| CIC 内核 | Coq 构造演算内核——健全性底座（求解器不可信，健全性在内核） |
| SMT 证书 | 求解器输出、可被内核独立核验；解不出时返回反例模型 |
| 生成器 + 验证器 | 算法自由、验证管输出（分配器贪心零证明；VeriLocc 2025 同构先例） |
| 证书层 | 验证「最优」而不只是「一致」——最优性证书（DP 表重放或 ILP 对偶） |
| Graph → Lattice 验证主线 | 8 项清单（备忘 §十二）——每项通过 = 三层链成立的证据 |
| 类型不变量 / 抽象规约 | 规约层 IR 条目形态（type invariant / abstract contract） |
| 边界条件（loop variant） | 循环终止性证明（变体递减） |
| 反例模型 | SMT 解不出时返回「哪个输入违反性质」——用户可读反例 |
| 证明驱动优化 | 已证性质回流入优化器（证明与优化互哺） |

## 十、指针安全与内存管理（`pointer-model.md`）

| 术语 | 含义 |
|---|---|
| PointerAnalysis（pts） | 建立 points-to 关系——指针可能指向的分配块 |
| RegionCheck | 区域逃逸检查——跨区域引用 outlives 判定（引用者存活区间 ⊆ 被引用区域存活区间）；存在区间的来源 |
| ProvenanceVerify | 解引用点边界验证（off + width ≤ alloc_size）——从 ALLOC 到 DEREF 的路径 = 安全证明 |
| 图锚定区域 | 区域 = 子图节点的字节域，非词法作用域影子；bump 分配 + 游标重置回收 |
| split / merge / share | 区域沿图边操作：划给子消费者 / 汇合点合并 / 分叉点只读共享 |
| alloc_at | 声明式进图：地址 + 大小 + 对齐声明式进图获得 provenance |
| provenance | 字节/指针的来源（ALLOC 节点）与归属 |
| 逃生舱入口 | 编译器无法追踪 provenance 的入口（外部地址/FFI/inline asm）→ `unsafe` |

## 十六、讨论判据与算法参考

| 术语 | 含义 |

## 十七、术语演进记录（2026-08-27）

| 旧 | 新 | 原因 |
|---|---|---|
