# pass.cr 伪代码
> 源文件：src/compiler/pass.cr（24 行）
> 功能概要：编译器扩展钩子调度器 —— 编译核心与插件之间的桥梁。核心在关键节点调用 pass_*（） 函数，各函数通过扩展管理器（ext_mgr）的 ext_dispatch_*（） 分发到已注册插件。不需要修改此文件来添加新插件，只需在 ext_plugins.cr 中注册新 handler，并在核心中加 pass_*（） 调用点。

## 函数 数组访问前处理（pass_before_array_access）
签名：`函数 数组访问前处理（pass_before_array_access）（数组变量（arr_var）：整数，索引变量（idx_var）：整数，字面量索引（idx_lit）：整数，数组长度字面量（arr_len_lit）：整数）-> 整数`
### 作用
在每次 IR：加载按索引（IR_LOAD_INDEX）/IR：存储按索引（IR_STORE_INDEX）指令生成之前由 IR 生成器调用，允许已注册插件拦截数组访问操作。返回 0 表示正常执行访问，返回 1 表示跳过此次访问。
### 逻辑
    将所有四个参数（数组变量、索引变量、字面量索引、数组长度字面量）原样转发给扩展管理器的 扩展：分发数组访问（ext_dispatch_array_access）函数，并直接返回该函数的返回值。
### 测试要点
1. 当无任何插件注册时，扩展：分发数组访问 应返回 0，表示正常执行访问
2. 当有插件返回 1 时，该次数组访问被跳过，IR 生成器不生成对应的 IR：加载按索引/IR：存储按索引 指令
3. 参数传递正确：数组变量（arr_var）和 索引变量（idx_var）是 IR 变量索引（可能为负数表示寄存器），字面量索引（idx_lit）和 数组长度字面量（arr_len_lit）是编译期已知的字面量

## 函数 二元运算后处理（pass_after_binary）
签名：`函数 二元运算后处理（pass_after_binary）（操作码（op）：整数，左操作数变量（lv）：整数，右操作数变量（rv）：整数，结果变量（result_var）：整数）-> 整数`
### 作用
在每次二元运算 IR 指令生成之后调用，允许插件进行溢出检查等后处理。返回整数值，语义由插件定义（通常 0 表示无异常）。
### 逻辑
    将所有四个参数（操作码、左操作数变量、右操作数变量、结果变量）原样转发给扩展管理器的 扩展：分发二元运算（ext_dispatch_binary_op）函数，并直接返回该函数的返回值。
### 测试要点
1. 无插件注册时，扩展：分发二元运算 返回默认值
2. 溢出检查插件可在此拦截并添加诊断信息或插入额外的 IR 指令

## 函数 分发调用（dispatch_call）
签名：`函数 分发调用（dispatch_call）（函数名索引（fn_ni）：整数，参数个数（ac）：整数，参数变量数组（arg_vars）：字符串）-> 整数`
### 作用
为 .so 动态库或标准库插件提供调用分发机制。当前为桩实现，始终返回 -1 表示未处理（调用方应根据返回值 -1 回退到默认调用路径）。
### 逻辑
    直接返回 -1。
    参数 函数名索引（fn_ni）（函数名索引）、参数个数（ac）（参数个数）、参数变量数组（arg_vars）（参数变量数组的字节缓冲区指针）均未使用——此函数尚未实现实际分发逻辑，目前是预留扩展点。
### 测试要点
1. 始终返回 -1，表示未找到处理者
2. 调用方应根据返回值 -1 回退到默认调用路径（直接生成 CALL 指令）
3. 参数不被读取或修改——纯桩实现
