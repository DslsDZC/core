## 函数 协程包装函数地址（goroutine_wrapper_addr）

### 作用

后端内建函数——返回协程入口包装器的地址。ELF 后端会拦截对此函数的调用并用实际虚拟地址替换，因此桩代码体永不执行。

### 逻辑

返回 0

### 测试要点

1. 在没有 ELF 后端的解释器模式下返回 0（无效地址）
2. 在 ELF 后端编译时被替换为实际包装器地址

## 函数 协程分配（g_new）

### 作用

创建新协程：先为该协程创建独立的竞技场，在竞技场中分配 16 千字节栈和 80 字节协程结构体，初始化纤程（其入口始终为协程入口包装器），设置协程结构体的所有字段。该函数不关心参数类型（参数类型未使用），保留用于将来扩展。

### 逻辑

// 先创建协程的竞技场：纤程栈和协程结构体必须位于协程自己的竞技场中，使其在协程退出前持续存在
令 竞技场编号（aid）= 新建竞技场（）
// 在协程的竞技场中分配栈（16 千字节 = 16384 字节）
令 栈底地址（stack）= 分配（16384）
令 栈顶地址（stack_top）= 栈底地址 加 16384 减 8  // 栈从高地址向低地址增长，预留 8 字节
// 初始化纤程。入口始终是协程入口包装器（由运行时启动代码或 ELF 后端发射），
// 它在运行时从此协程结构体的偏移 56 和 64 读取保存的函数和保存的参数，
// 调用 保存的函数（保存的参数），并将结果发送到结果通道（偏移 40）。
令 包装函数地址（wrap_addr）= 协程包装函数地址（）
令 栈指针（sp）= 纤程初始化（栈顶地址，包装函数地址）
// 分配协程结构体（80 字节），位于协程自己的竞技场中
令 协程句柄（g）= 分配（80）
令 协程编号（id）= 下一个协程 ID
令 下一个协程 ID = 下一个协程 ID 加 1
写 64 位（协程句柄，0，协程编号）         // 偏移 0：协程编号
写 64 位（协程句柄，8，0）               // 偏移 8：状态设为可运行（0）
写 64 位（协程句柄，16，栈指针）          // 偏移 16：栈指针
写 64 位（协程句柄，24，栈底地址）        // 偏移 24：栈低地址
写 64 位（协程句柄，32，竞技场编号）       // 偏移 32：竞技场编号
写 64 位（协程句柄，40，0）               // 偏移 40：结果通道 = 0（默认，由调度启动协程覆写）
写 64 位（协程句柄，48，-1）              // 偏移 48：下一节点 = -1（链表末尾）
写 64 位（协程句柄，56，入口函数指针）     // 偏移 56：保存的函数
写 64 位（协程句柄，64，协程参数）         // 偏移 64：保存的参数
写 64 位（协程句柄，72，0）               // 偏移 72：临时值 = 0
返回 协程句柄

### 测试要点

1. 创建协程后下一个协程 ID 递增
2. 栈分配在协程自己的竞技场中
3. 协程结构体所有字段正确初始化
4. 纤程入口为协程包装函数地址
5. 状态初始为可运行（0）

## 函数 协程释放（g_free）

### 作用

销毁协程：重置其竞技场（回收栈和协程结构体内存），将状态标记为已死（3），防止被重新调度。

### 逻辑

令 竞技场编号（aid）= 读 64 位（协程句柄（g），32）  // 读取偏移 32 处的竞技场编号
重置竞技场（竞技场编号）  // 回收纤程栈和协程结构体（两者均位于该竞技场中）
写 64 位（协程句柄，8，3）  // 偏移 8：标记状态为已死（3），确保永不重新入队

### 测试要点

1. 竞技场被重置，内存被回收
2. 状态被设为已死（3），不会再次入队
3. 多次释放同一协程的安全性由竞技场重置检查竞技场编号合法性保证
