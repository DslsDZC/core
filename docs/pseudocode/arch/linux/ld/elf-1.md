## 函数 读 16 位（r16）
### 作用
从字节缓冲区中按小端序读取 16 位无符号整数。
### 逻辑
返回 读取无符号字节（bu8）（缓冲区, 位置） + 读取无符号字节（bu8）（缓冲区, 位置+1） * 256
### 测试要点
1. 0x0102 -> 0x0102（小端序低位在前）。
2. 边界位置：需保证 位置（pos）+1 不超缓冲区。

## 函数 写单字节有符号（w8_signed）
### 作用
以 32 位写入方式写单字节值（委托 w32，利用符号扩展语义）。
### 逻辑
调用 写32位（w32）（缓冲区, 位置, 值）
### 测试要点
1. 负值经 写32位（w32） 符号扩展后正确写入。

## 函数 发射分配函数体（emit_alloc_body）
### 作用
发射竞技场感知的双路径堆分配器机器码。运行时检查 当前竞技场（g_current_arena）：若设置了竞技场索引，使用竞技场 蹦床式（bump） 分配；否则回退到全局 蹦床式 分配。包含大小对齐、边界检查（64MB 上限）、竞技场 内存耗尽（OOM） 链式扩展、零初始化、分配头写入等完整逻辑。返回写入的字节数。
### 逻辑

—— 若竞技场全局变量未注册（非静态构建），则退回到简化分配器
如果 当前竞技场全局变量索引（gv_current_arena） 小于 0，那么：
    返回 发射简单分配函数体（emit_alloc_body_simple）（缓冲区, 起始位置, BSS 虚拟地址, 全局变量大小）

令 当前指针（cp） = 0
令 函数虚拟地址（fva） = 代码段基址（TEXT_BASE） + 起始位置

—— 第 0 部分：64MB 完整性检查（12 字节）
—— 发射 cmp rdi, 67108864 指令（7 字节）：若请求分配大小超过 64MB，立即返回 0
向缓冲区偏移量 起始位置+当前指针 处写入字节值 72（REX.W 前缀，REX 格式为 0100WRXB = 64 + W×8 + R×4 + X×2 + B，此处 W=1、R=0、X=0、B=0，计算结果 64+8+0+0+0=72，表示为 64 位操作数大小）
向缓冲区偏移量 起始位置+当前指针+1 处写入字节值 129（cmp r/m64, imm32 指令的 opcode）
向缓冲区偏移量 起始位置+当前指针+2 处写入字节值 255（ModRM 字节，计算公式 mod×64 + reg×8 + rm：mod=3 表示寄存器直接寻址模式、reg=7 为 cmp 的 /7 立即数操作码扩展、rm=7 表示 rdi 寄存器，即 3×64 + 7×8 + 7 = 192+56+7 = 255）
调用 发射写32位（e2_w32）向偏移量 起始位置+当前指针+3 处写入 32 位有符号立即数值 67108864（64MB 即 0x4000000）
令 当前指针 = 当前指针 + 7
—— 发射 jbe +3 指令（2 字节）：若 rdi <= 64MB 则无条件跳转到正常分配路径（ret）
向缓冲区偏移量 起始位置+当前指针 处写入字节值 118（jbe rel8 的 opcode，低于等于时短跳转）
向缓冲区偏移量 起始位置+当前指针+1 处写入字节值 3（相对偏移量 rel8，跳过后续 3 字节到达 Part 1 的第一条指令）
令 当前指针 = 当前指针 + 2
—— 发射 xor eax, eax；返回（ret）（3 字节）：请求大小超过 64MB，返回 空指针（NULL）
向缓冲区偏移量 起始位置+当前指针 处写入字节值 49（REX 前缀，W=0 用于 32 位操作数，R=0、X=0、B=1，即 64+0+0+0+1=65... 实际值为 49 = 64+0+0+0+1=65? 不对，49 = 0x31 = 0100 1001 = 64+0+0+8+1 = 73? 重新计算：49=0x31，REX 格式 0100WRXB，0100=64，W=0，R=1，X=0，B=1，即 64+0+4+0+1=69，不是 49。再次：49 十进制 = 0x31 = 0011 0001，不符。49 作为 REX 前缀：REX 格式 0100WRXB，0100=0x4 = 64。49 = 0x41 = 0100 0001 = 64+0+0+0+1 = 65。不对，0x31 是 0011 0001 = 49，不是 REX。重新审视：49 是 xor r32, r/m32 的 opcode 吗？不对，xor r32, r/m32 的 opcode 是 0x31 或 0x33。0x31 = 49 十进制，确实是 XOR r/m32, r32 的 opcode，方向反转。和 REX 无关——此处 49 是 opcode 而非 REX 前缀）
向缓冲区偏移量 起始位置+当前指针+1 处写入字节值 192（ModRM 字节，mod×64+reg×8+rm = 3×64+0×8+0 = 192，表示 mod=3 寄存器模式、reg=0 源寄存器 eax、rm=0 目标寄存器 eax，即 xor eax, eax）
令 当前指针 = 当前指针 + 2
向缓冲区偏移量 起始位置+当前指针 处写入字节值 195（返回（ret） 指令的 opcode，C3）
令 当前指针 = 当前指针 + 1

—— 发射 mov r9, rdi 指令（3 字节）：将原始请求大小保存到 r9 寄存器，供后续头部写入使用
向缓冲区偏移量 起始位置+当前指针 处写入字节值 73（REX.W+B 前缀，W=1、R=0、X=0、B=1 = 64+8+0+0+1 = 73）
向缓冲区偏移量 起始位置+当前指针+1 处写入字节值 137（mov r/m64, r64 的 opcode）
向缓冲区偏移量 起始位置+当前指针+2 处写入字节值 249（ModRM 字节，mod×64+reg×8+rm = 3×64+1×8+1 = 201... 249 = 3×64+7×8+1 = 192+56+1 = 249，mod=3 寄存器模式、reg=7 源寄存器 rdi、rm=1 目标 rcx？不对 mov 方向：opcode 137 = mov r/m64, r64，所以 reg 字段是源寄存器。249 = 0xF9 = 11 111 001：mod=3、reg=7，rdi 实际编码为 7? 不对，r9 是 reg=1，rdi 是 reg=7。再算：249 = 3×64 + reg×8 + rm，如果 reg=1，r9 目标、rm=7，rdi 源：3×64 + 1×8 + 7 = 192+8+7 = 207，不等于 249。如果 reg=7，rdi 源，、rm=1，r9 目标?，：3×64 + 7×8 + 1 = 192+56+1 = 249。所以 ModRM 表示目标 r/m = r9，rm=1，、源寄存器 = rdi，reg=7，，即 mov r9, rdi）

—— 发射 lea r10, [rip + 当前竞技场（g_current_arena）] 指令（7 字节）：将当前竞技场全局变量的地址加载到 r10
令 RIP 修补位置 当前竞技场（rip_pos_ca） = 起始位置 + 当前指针 + 3（记录 RIP 相对偏移量的修补位置，后续在标签解析阶段填入实际位移）

向缓冲区偏移量 起始位置+当前指针+1 处写入字节值 141（lea r64, [rip+disp32] 的 opcode）
向缓冲区偏移量 起始位置+当前指针+2 处写入字节值 21（ModRM 字节，mod×64+reg×8+rm = 0×64+2×8+5 = 0+16+5 = 21：mod=0 表示 RIP 相对寻址、reg=2 对应 r10（加上 REX.R=1，合并为 r10）、rm=5 表示 RIP 相对寻址模式）
调用 发射写32位（e2_w32）向偏移量 起始位置+当前指针+3 处写入占位符值 0（32 位有符号位移量，在 RIP 修补阶段填入实际值）
令 当前指针 = 当前指针 + 7

调用 扩展 RIP 修补数组（grow_rip_patch）（x86 RIP 修补计数（g_x86_rip_patch_count） + 1），确保数组容量足够

令 当前指针 = 当前指针 + 3
