## 零、结论摘要

1. **该用能力**——v1 方向成立，但职责边界修正：能力不是「存储位置的原语」（那是条目标识 + 偏移，已定稿），而是**不可重算结构的身份与授权机制**
2. **判据 = 表达范围**：存储半边（缓存语义，已定稿）∪ 执行标注空间（非因果/模糊/超图灵/共归纳，dataflow-design §8）——后者突破「值 = 配方」公理，强制需要句柄 + 授权
3. 能力 = ⟨身份符号, 授权集, 域约束, 派生源⟩；基址/长度/字节 R/W/X 明确排除（经典映射实例）
4. 结构 = 能力树（seL4 CNode / KeyKOS-EROS 先例）：寻址/派生/撤销/隔离一体，无额外表
5. 代数 = PCM × 布尔格（+可复制性）：区域分量 PCM（分离组合），授权分量幂集格（⊆ 细化）；分级扩展点 = 分数权限
6. 兑现 = 语义层图数据，编译期消费：运行期经典路径零新增 + 图边界一次授权检查（Crary-Walker-Morrisett 静态能力先例，零运行时开销有形式化证明）
7. **三层映射定位（v3）**：图 = 关系空间（跨范式语义中轴）、格 = 状态/存储空间（内存模型 = 中间存在空间）、二进制 = 物理编码空间；跨范式发生在图层，超图灵性属于图不属于格；格的价值 = 表达空间未被有限范式封顶（§四）
8. **能力不提升顶层原语（v3）**：v2「该用能力」保留，追加边界——能力 = 图上「可能关系」的实例（A ──可能执行──> B），与模糊/非确定统一；只有当图 + 格 + 映射规则无法自然表达时才提升为一等概念（§六）
9. **验证主线（v3）**：Graph → Lattice 映射通用性 8 项清单（§十二）——因果 / 非因果 / 模糊 / 非确定 / 并发异步 / 反馈 / 超图灵 / 格层不重引入顺序执行

## 一、背景：抽象升华系列（v1 保留）

1. **核心语义 = 数学/逻辑/结构，零硬件惯例**——惯例只允许以「后端实现选择」或「可忽略注解」存在
2. **范式普适**：语言要跨越所有范式（量子、分布式、GPU、未来未知范式）
3. **用户面上手成本极低**：内部可以复杂（编译器承担），表面必须简单

## 二、位置抽象的两难（v1 保留）

```
太复杂（全一般理论，如完备格代数全套）
  → 上手成本爆炸——用户要学格运算

太低端（纯 1D 扁平地址）
  → 范式特例跨不过——量子寄存器（纠缠是位置间关系，不是顺序）、
    分布式（node 是身份不是偏移）、GPU（bank 冲突）
```

## 三、结构性论证：位置识别的两种必然形式（v1 保留）

「存东西」要求位置**可识别**。「指认位置」只有两种结构：

```
有序的位置 → 偏移原语（±4、连续坐标）
命名的位置 → 标签原语（内容寻址=hash、图节点、属性标识、句柄）
```

纯值流范式（函数式/数据流）**无位置概念**——位置抽象自动失效（§五 半边二的 CORE 共归纳即此例）。

## 四、三层映射：图 → 格 → 二进制（v3 新增）

> 2026-08-26 讨论补入架构总纲：图 = 跨范式语义中轴（dataflow-design §8），格 = 内存模型 = 中间存在空间（本备忘），二进制 = 机器编码。此前各节在层内讨论（表达范围/能力/代数），本节回答「格为什么是第二层」。

```
不同范式 / 计算语义
        ↓
       图（HDFG）       —— 关系空间：发生什么
        ↓ 图 → 格映射
       格（内存模型）    —— 状态/存储空间：如何存在
        ↓ 格 → 二进制映射
     Binary / Machine  —— 物理编码空间：如何实现
```

### 4.1 为什么需要格这一层

图回答「这个计算世界中有什么关系、什么可能发生」；格回答「这些东西如何成为具有状态和位置的可实现存在」。若图 → 二进制直连，大量「如何存在」的问题（节点是什么内存对象、关系怎么保存状态、两个可能分支的状态怎么共存、非因果怎么落地址、节点生命周期）都会被迫塞进一个万能的图→机器码映射器。

### 4.2 三层的数学定位

- **图 = 关系空间**：表达可超越经典图灵机执行模型的语义（非因果、模糊、超图灵）——**超图灵性属于图，不属于格**
- **格 = 状态/存储空间**：提供足够一般的状态模型使图能够被映射下来；格不需要「理解超图灵」，只需让可被当前执行环境实现的部分拥有状态/位置/关系/可访问性
- **二进制 = 物理编码空间**：把格编码成具体机器的地址、字节、指令、位模式
- **格不重新引入「程序顺序」**：传统 IR（SSA/LLVM）本质上仍是「另一种程序」——按执行路径组织；格 = 中间存在空间，不必重新引入程序顺序。这是三层链成立的关键判据（见 §十二 清单第 8 项）

### 4.3 跨范式自由度（格的价值）

「跨范式用格」比「格作为内存模型」更准确：

- 不同范式（命令式/函数式/数据流/并发/事件驱动/非确定/模糊/超图灵）的差异首先被图吸收（图层标注空间，dataflow-design §8）
- 格不被某个有限、固定的传统计算范式预先封顶——允许递归构造、关系组合、无界规模，可构造表达空间无界
- 于是真正的问题是「C 的语义能否找到一个格映射」，而不是「格能不能表示 C」——**格本身不需要知道范式是什么**

### 4.4 术语澄清：格的两义

「格」在本备忘（及全仓库）有两义，阅读时先判定语境：

| 术语 | 含义 | 位置 |
|---|---|---|
| 格（层） | 内存模型 = 中间存在空间（第二层映射） | 本节；`docs/memory-model.md` |
| 格（Lattice） | 层内组织代数成分（偏序 + join/meet） | §九 代数（PCM × 布尔格） |

两者是「层与层内结构」的关系，不是两个概念。本备忘 v2 的「设计决定用格」（§六）即指格层采用含格成分的组织代数，非独立概念。

## 五、表达范围（v2 判据推导）

表达范围 = 系统必须表达的语义，分两半边：

### 半边一：存储（缓存语义，已定稿）

memory-model.md §一 七条条款：值 = 配方、驱逐不变量、再生等价、边界公理、赋值 = 版本化、地址 = 映射、映射实例正确性。位置语义 = (条目标识, 偏移)；区域 = 图锚定字节域（推论 B: split/merge/share）；字节权限层（Freeable > Writable > Readable > Nonempty > Empty）= **经典映射实例的权限面**（条款 7），非语义本体。

### 半边二：执行标注空间（dataflow-design §8）

| 结构 | 要表达什么 | 对语义公理的突破 |
|---|---|---|
| FIXPT 非因果环 | 不动点（μ/ν, Knaster-Tarski），声明性、执行后置（PSPACE 难） | 再生等价（不可重算） |
| FUZZY 模糊软分支 | 格值隶属度（剩余格），两路都执行按隶属度加权融合 | 分支互斥 + 可重算（融合共享归属） |
| 超图灵·神谕 | 「此节点计算函数 F」，F 可不可计算；验证 = 逃生舱（unsafe 同层） | 值 = 配方（无配方条目） |
| 超图灵·连续（BSS） | 无限精度实数 = 原子符号 | 值 = 配方（无限信息） |
| 超图灵·超限（ITTM） | 序数时间位置、limsup 极限阶段 | 有序位置原语扩展（链/格） |
| CORE 共归纳 | 流 = 终余代数（CoNode），有限前缀可算 | 无（纯值流范式，§三 豁免） |

**关键判据**：缓存语义条款 1–3（值 = 配方 / 驱逐不变量 / 再生等价）只覆盖**可重算结构**。§8 的不可重算结构（神谕、BSS 实数、FIXPT 声明、模糊融合）需要**不可配方的身份 + 授权**——这正是能力的职责所在。

## 六、该不该用能力 → 用，但职责重划

> **v3 修订（2026-08-26）**：v2 结论「该用能力」保留，追加定位约束——**能力不提升为语言顶层 primitive**。能力 = 图上「可能关系」的实例（A ──可能执行──> B），与 FUZZY 模糊分支 / 非确定路径 / 非因果统一（都是图的关系语义，不是独立类型）；consult/assume/measure/pass 授权标注即「可能关系」的落地形态（§七 身份符号指向的正是 §五 半边二 的不可重算结构）。只有当「图 + 格 + 映射规则」无法自然表达时（确实需要独立生命周期 / 权限 / 内存布局 / 执行语义），才把能力提升为一等概念——判定见 §十二 清单。

能力三件套（CHERI 式句柄/权限/边界）对照表达范围：

| 能力成分 | 表达范围对照 | 结论 |
|---|---|---|
| 句柄（不可算术的身份） | 可重算侧：条目标识（配方身份）已覆盖；**不可重算侧：神谕/BSS 实数/FIXPT 声明需要符号身份** | 身份符号 = 能力成分 |
| 边界 | ProvenanceVerify 已覆盖（off + width ≤ alloc_size，2026-08-16 统一） | 已定稿不动；能力的对应物 = 域约束（类型签名） |
| 权限 | 字节 R/W/X = 经典映射实例（字节权限层）；**语义授权（consult/assume/measure/pass）= 不可重算侧的独占地盘** | 授权集 = 能力核心成分 |

- 格的组织职责（区域包含/组合/细化）保留——「设计决定用格」成立
- 能力的不透明句柄机器形态（CHERI tag）不进语义层——语义层一切透明（值 = 配方）；不透明是经典机器防护形态（威胁模型差异，§十一）
- 先例与约束：Karger & Herbert 1984（能力架构 + 格安全组合；Traceability of Access = 派生追踪）；Kain 1986 警告——不是所有能力设计都能强制格策略，**约束 = 细化 ⊑ 必须可强制**

## 七、能力成分（v2 定形）

能力 = **⟨身份符号, 授权集, 域约束, 派生源⟩**

| 成分 | 内容 | 对应表达范围 |
|---|---|---|
| 身份符号 | 指向什么——神谕符号、BSS 实数符号、声明式不动点名 | §8 无配方条目的符号身份 |
| 授权集 | 能做什么——语义操作枚举：consult（咨询神谕）/ assume（假设不动点）/ measure（测量）/ pass（传递派生权） | 逃生舱授权（unsafe 同层）、声明性执行授权 |
| 域约束 | 适用边界——神谕类型签名 F: ℕ→ℕ 等 | 语义边界（非字节长度） |
| 派生源 | 从哪个声明/能力派生而来 | 逃生舱授权必须可追踪（信任链） |

**排除**：基址/长度/字节 R/W/X——经典映射实例（字节权限层已有定稿；CompCert+Iris 实例为其形式化对应，见 §十四）。

## 八、结构：能力树（v2 定形）

- **能力树**（seL4 CNode / KeyKOS-EROS 节点树先例）：每子图一棵——寻址（树路径）、派生（mint/copy 沿树）、撤销（剪枝/alloc count 失效）、隔离（每域一棵）——**一个结构**
- **表是多余的**：命名树的层级 ≠ 语义层级——平级符号（神谕/实数）只是树上的叶子。表/树不是二选一：树的层级命名空间覆盖表的一切职责（寻址/隔离/撤销）
- 共享/融合：Copy 别名（多槽引用同一对象）；merge/share 是区域代数的语义（§九 PCM），不归寻址结构管
- **兑现 = 编译期**：能力树是语义层图数据（与字节权限层同定位），能力流分析编译期消费，证明完毕不下发。KeyKOS/EROS 的运行期教训反证：树遍历太贵（prepared keys + 两级缓存才摊平）——Core 直接编译期消灭
- 用户面：声明式进图（alloc_at 先例：声明即注册、生命周期随子图），句柄不透明——零管理，上手成本不变

## 九、代数：PCM × 布尔格（v2 定形，替代积格/纯格）

### 候选品谱系（v1 §四 保留 + v2 判决）

| 候选 | 第一原语 | 判决（v2） |
|---|---|---|
| 格（Lattice） | 偏序 + join/meet | 组织职责保留，但作为能力代数不够精确（见下） |
| PCM（偏交换幺半群） | 分割/组合 `·` | 区域分量采用（分离逻辑底座） |
| 树/层级 | 唯一父结构 | 命名/派生结构采用（§八），非代数 |
| 向量空间 | N-D 坐标 | 否决（区域/组合语义缺席） |
| 能力模型（Capability） | 句柄 + 权限 | 采纳，职责重划（§六/§七） |

### 淘汰判决

| 候选 | 判决 |
|---|---|
| 积格（区域格 × 授权格） | 区域分量不是全格（树 + 部分 merge）——总 join 制造无意义合并，丢分离精确性——**否决** |
| 纯 PCM | 授权细化（⊆ 收窄）不是 PCM 的组合导出序——**否决** |
| 剩余格（FUZZY 同构） | 分级授权不在当前表达范围（模糊加权在数据层，不在授权层）——**扩展点** |
| **PCM × 布尔格（+可复制性）** | **采用** |

### 结构

- **区域分量 = PCM**（偏交换幺半群）：`·` 分离组合（部分、精确），序从组合导出（a ⊑ b ⟺ b = a·c）——Iris ghost state / Boyland 分数权限 / separation algebra 同构
- **授权分量 = 幂集格**（布尔格）：授权集 ⊆ 收窄 = 细化 ⊑，∩/∪ = meet/join；**可复制性区分**（Iris 1.0→1.1 RA duplicable core 教训）：只读/consult = 可复制（share），写/assume = 独占
- 总序：`(r₁,a₁) ⊑ (r₂,a₂) ⟺ r₁ ⊑ r₂ ∧ a₁ ⊆ a₂`（保序积）
- 分级扩展点：分数权限 π ∈ (0,1]（Boyland）与模糊隶属度 [0,1] 同构——未来模糊分级授权直接复用，当前 YAGNI

## 十一、诚实的代价（v1 §七 修订：兑现账单）

- **性能**：经典路径**零新增**（能力 = 编译期图数据，证明完毕不下发）；图边界一次授权检查（与已有 sub+cmp+jae+ud2 同级）；不可重算结构无当前后端（§8 执行后置）→ 零
- **威胁模型**：seL4/CHERI 防恶意代码 → 运行期强制（CSpace 走查是 IPC 已知瓶颈）；Core 编译器可信 → 编译期证明 + 图边界触点——**参照 seL4 的结构，不参照其运行时机制**
- **工程量**（真成本）：能力流分析（PointerAnalysis 推广，O(N×P) 图上稀疏分析）+ 三 pass 能力化重写——内存模型层面大改

## 十二、Graph → Lattice 映射通用性验证清单（v3 新增）

> 2026-08-26 讨论收敛：当前最值得验证的问题不再是「要不要加 Capability」，而是「Graph → Lattice 映射是否真的足够通用」。8 项全部成立时，三层结构形成闭环哲学：**图负责表达计算，格负责承载计算，二进制负责实现计算**。

| # | 测试 | 要点 |
|---|---|---|
| 1 | 普通因果程序能否映射 | 现值流路径（DAG/顺序），已知成立——缓存语义条款 1–3 |
| 2 | 非因果结构能否映射 | FIXPT 声明（μ/ν 不动点）——不可重算身份需要能力（§六） |
| 3 | 模糊分支能否映射 | FUZZY 加权融合——融合共享归属（区域 share，memory-model.md 推论 B） |
| 4 | 非确定计算能否映射 | 可能路径——格层不要求立即坍缩为单一执行路径 |
| 5 | 并发/异步能否映射 | go/flow/yield/recv——区域隔离 + 消息区域（memory-model.md） |
| 6 | 反馈结构能否映射 | ITER 环（现状 region 嵌套已有）→ 格层无新增 |
| 7 | 超图灵语义能否表达 | 图层表达（神谕/BSS/ITTM 标注，dataflow-design §8）；格层只需合理表示——「格层不实现超图灵」本身就是设计点 |
| 8 | 格层不会重引入顺序执行 | **关键判据**：格 = 中间存在空间，不是「另一种程序」——验证格层不存在隐含的程序计数器 / 基本块 / 执行路径组织 |

- 每项通过 = 先规格后证明（进入 §十三 开放问题逐项收敛）；全部成立后再评估能力是否需提升为一等概念
- 完成度追踪见 `TODO.md`
